# Go/No-Go task (PsychoPy)

PsychoPy implementation of the visual Go/No-Go task used to collect the EEG
data analysed in this repository.

Authors: Elena Scarpa, Giovanni Lazzaro

## Contents

| File | Description |
|---|---|
| `gonogo_task_list1.psyexp` | The task in the PsychoPy **Builder** format (open it in Builder to view or edit the routines) |
| `gonogo_task.py` | The task as a **Coder** script (generated by Builder v2023.2.3, cleaned for release); lets you choose the condition list at start-up |
| `generate_conditions.py` | Creates a pseudo-randomised condition list `conditions/CONDITION_<list>.xlsx` |
| `matlab/PseudoRandomCondition.m` | Same generator in MATLAB |
| `conditions/CONDITION_1.xlsx` | Condition list 1, as used for data collection (200 trials: 160 Go, 40 NoGo) |

## Requirements

- [PsychoPy](https://www.psychopy.org/download.html) **2023.2.3** (the version used for data collection; newer versions should work but were not tested)
- `pyserial` (included in PsychoPy standalone) if you send triggers through a serial trigger box
- A keyboard (responses with the space bar)

## Quick start

1. Clone the repository and open `task/gonogo_task.py` in the PsychoPy Coder
   (or `task/gonogo_task_list1.psyexp` in the Builder; in that case set the serial port in the `trigger_stimuli` code component).
2. Edit the **CONFIGURATION** block at the top of the script:
   - `SERIAL_PORT`: the serial port of your trigger box (e.g. `'COM3'` on Windows, `'/dev/ttyUSB0'` on Linux).
   - `USE_SERIAL_TRIGGERS = False` to try the task without trigger hardware (triggers are then only written to the log file).
3. Make sure the condition list exists in `task/conditions/` (or create one, see below).
   Only list 1 is currently included; lists 2 and 3 will be added.
4. Run the script, fill in *participant*, *session* and *list* in the dialog.
5. Data are saved in `task/data/` (`.csv`, `.psydat`, `.log`). This folder is ignored by git.

Press `Esc` at any time to quit.

### Creating a condition list

```bash
cd task
python generate_conditions.py --list 1 --seed 1
```

Defaults: 200 trials, 80% Go / 20% NoGo, first trial Go, no consecutive NoGo trials.
Use `--n-trials`, `--p-go`, `--seed` to change them. Columns of the file:

| Column | Values | Used for |
|---|---|---|
| `stim_type` | `go` / `nogo` | stimulus trigger |
| `Color` | `green` / `red` | fill colour of the circle |
| `corrAnswer` | `space` / `none` | response trigger and accuracy |

## Trial structure

As implemented in `gonogo_task.py`:

1. **Instructions** — until the space bar is pressed.
2. For each of the trials in the condition list:
   - **Pre-stimulus interval** (blank screen) — random duration of 0.5, 0.75 or 1 s.
   - **Stimulus** — a circle (0.25 screen height) in the centre of the screen: green = Go, red = NoGo.
     It stays on screen for up to 1 s and disappears as soon as the space bar is pressed. The response window is 1 s.
   - **Inter-trial interval** (blank screen) — 0.5 s.
3. **Pause** — self-paced (space bar to continue) before trial 101.
4. **End screen** — until the space bar is pressed.

On-screen texts are in Italian; edit the `text=` arguments of the `TextStim`
components to translate them.

## EEG triggers

Triggers are written as single bytes to the serial port and are time-locked to
the screen flip.

| Code | Marker | Event |
|---|---|---|
| 2 | S2 | Go stimulus onset |
| 8 | S8 | NoGo stimulus onset |
| 4 | S4 | Space bar pressed on a Go trial (correct response) |
| 5 | S5 | Space bar pressed on a NoGo trial (commission error) |
| 0 | — | Reset |

Omissions (no response to Go) and correct rejections (no response to NoGo) have
no marker; they are identified offline as stimulus triggers not followed by a
response trigger.

## Known issues

The script reproduces the version used for data collection, including these behaviours:

- **`key_resp_2.corr` is not reliable.** Responses are stored as a list
  (e.g. `['space']`), so the correctness check against `corrAnswer` is always
  false for Go responses. Compute accuracy offline from `stim_type` and
  `key_resp_2.keys` (or from the EEG triggers).
- **Response triggers are not reset to 0.** Because of a typo
  (`resp_pulse_stared`), the reset after a response trigger is never sent; the
  line is reset at the next stimulus trigger. With trigger boxes that mark
  value changes this does not affect the markers, but check it with your hardware.
- **Response trigger timing.** The response trigger is sent on the next screen
  flip after the key press (≤ 1 frame delay). Use the trigger for
  epoching and `key_resp_2.rt` for reaction times.
